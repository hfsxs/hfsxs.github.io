Zabbix监控系统的部署与配置

Zabbix，由C语言开发的开源分布式企业级监控系统，通过Agent方式采集服务器、应用程序、网络服务、数据库、网站及其他网络硬件的工作状态，最终将监控数据写入数据库。Zabbix具备分布式监控功能，支持复杂架构下的监控解决方案，还提供直观的web页面展现。Zabbix告警通知机制也比较灵活，如邮件、短信和其他报警方式，以便于快速定位、解决各种故障，从而保障业务统的安全与稳定

体系架构

Zabbix是典型的C/S架构，Zabbix Server作为服务端通过Zabbix Agent或SNMP协议等方式，定期收集被监控端的监控数据并其存储到数据库，最后通过前端UI做展示

1.Zabbix Server

Zabbix Server，Zabbix监控服务端，核心部分，负责监控数据的采集、计算及存储，并依据监控指标所设置的触发器阈值生成告警信息，进而完成告警动作，如发送告警信息（邮件、微信、短信及钉钉等）、运行命令（如shell命令、reboot、restart、install等），以进行故障处理或通知

2.Zabbix Agent

Zabbix Agent，部署于被监控端，收集本地资源和应用程序的状态，并将收集到的数据发送给Zabbix Server

3.Zabbix Proxy

Zabbix Proxy，可选组件，用于分流Zabbix Server的负载，类似于中转站，将收集到的数据转发给Zabbix Server，实现整个监控系统分布式的架构

4.数据库

Zabbix配置信息及监控数据的后端存储，支持MySQL、Oracle等主流数据库，官方推荐MySQL

5.UI

前端Web界面，根据收集到的数据进行展示和绘图，属于Zabbix Server，可部署于同一服务器

功能组件

1.zabbix_server

Zabbix服务端守护进程，接收其余组件采集到的监控数据，如zabbix_agent、zabbix_get、zabbix_sender、zabbix_proxy、Zabbix_ java_ gateway等

2.zabbix_agentd

Zabbix客户端守护进程，负责收集客户端数据，如CPU 负载、内存、硬盘使用情况等

3.zabbix_proxy

Zabbix分布式架构代理守护进程，通常监控设备大于500时需要进行分布式监控架构部署

4.zabbix_get

Zabbix数据接收工具，单独使用的命令，通常在server或proxy端执行获取远程客户端信息的命令

5.zabbix_sender

Zabbix数据发送工具，发送数据给server或proxy端，通常用于耗时比较长的检查

6.zabbix_java_gataway

java网关，专用于java的agentd，只能主动取获取数据，而不能被动获取

应用场景

1.操作系统

CPU负载与使用率、内存使用率、磁盘空间与IO、系统进程、系统日志、网卡状态及流量等

2.服务器硬件

Zabbix通过IPMI（Intelligent Platform Management Interface，智能平台管理接口）协议跨越不同的操作系统、固件和硬件平台直接与服务器进行通信，并获取硬件相关的状态与性能，如温度、风扇转速、电源状态等

3.网络设备

Zabbix通过SNMP（网络管理协议，Simple Network Management Protocol，用于监控和管理网络节点与设备的应用层协议，如服务器、工作站、路由器、交换机）协议监控路由器、交换机、防火墙、UPS、温度传感器、传真机和负载均衡等硬件设备的状态，如流量、错误包率、端口状态、防火墙规则、连接数、负载均衡状态等，还能解析 Cisco、华为等厂商的MIB库

4.应用程序

Zabbix可用于监控Web服务器和应用服务器的HTTP请求、响应时间、连接数等指标，对DNS、DHCP、SMTP等网络服务，可监控其可用性、响应时间、错误率等指标，对于数据库服务器可监控数据库的查询性能、连接数、缓存利用率等指标。此外，对于Java程序，通过JMX协议（Java Management Extensions）进行通信，以获取其运行状态，如堆内存使用情况、线程数、GC时间等，并通过这些指标判断其性能和健康状态

5.容器

Zabbix可用于监控容器化应用程序的状态、性能和资源利用率，如Docker、Kubernetes等

6.自定义监控

Zabbix agent支持执行自定义命令返回监控结果，以实现更复杂监控需求，如使用Shell脚本监控某些业务场景

核心概念

1.主机

host，主机，被监控的设备，以IP或域名表示

2.主机组

host group，主机组，逻辑概念，包含主机和模板，通常用于给不同用户组的主机分配权限

3.监控项

item，监控项，即监控指标，通常是度量数据，由key标识，如vm.memory.size[pavailable]，表示内存使用率

4.触发器

trigger，触发器，用于定义监控的监控值是否在正常阈值的逻辑表达式，超过阈值责备认为是故障，触发器从“OK”变成“Problem”状态，直到恢复，触发器再返回一个“OK”的状态，表示故障恢复

5.事件

event，事件，触发器触发的特定事件，或zabbix定义的一个自动上线注册主机的事件

6.动作

action，动作，Zabbix触发器触发时预定义的特定事件处理的具体措施，如执行脚本，或向管理员邮箱发送告警邮件等

7.媒介

media，媒介，发送告警通知的手段和途径，如邮件、钉钉等

8.Web场景

web scenario，Web场景，用于检测web站点可用性的一个或多个HTTP请求

9.模版

template，一组可被应用到被监控主机的预设条目集合（如监控项、触发器、Web场景等），用于主机的快速监控与监控任务的批量修改，将这些设置好的规则直接关联到主机

配置流程

1.安装Zabbix Agent

2.创建主机

Zabbix UI登录，创建一个host，即要监控的设备或应用程序，并为主机指定一个唯一的名称，设置主机的IP地址或DNS名称，再选择适当的监控方式（如Agent、SNMP等）

3.创建监控项

为主机创建用于采集数据监控项（也可以关联监控模板），监控项定义了要监控的指标，如CPU使用率、内存使用率、磁盘空间等，并选择适当的监控方式（例如通过Zabbix agent、SNMP、JMX等）和相应的键值，以及采集数据的间隔时间

4.创建触发器

监控项被定义后，需要创建触发器，用于触发告警动作。触发器定义了异常情况的条件，如CPU负载过高、网络连接超时等。设置合适的条件表达式，以及设置触发器的优先级和严重性级别

5.配置告警动作

触发器定义后，需要配置告警动作（action），即在触发器被触发后所采取的操作。Zabbix支持电子邮件、短信、钉钉、企业微信、执行脚本等等多种方式进行告警。最后为每个动作指定相应的操作，如发送给管理员、发送给特定用户组等

1.安装依赖包

apt install -y gcc mysql-dev libsnmp-dev libevent-dev libxml2-dev libghc-curl-dev
yum instal -y gcc make curl-devel mysql-devel net-snmp-devel libcurl libxml2-devel

2.安装Nginx、PHP、MySQL

3.创建Zabbix用户与组

groupadd zabbix && useradd -g zabbix -s /sbin/nologin zabbix
mkdir -p /var/log/zabbix && chown -R zabbix:zabbix /var/log/zabbix

4.编译安装Zabbix Server

tar -zxvf zabbix-6.0.18.tar.gz && cd zabbix-6.0.18
./configure --prefix=/usr/local/zabbix --sysconfdir=/etc/zabbix \
--enable-server --enable-agent --enable-proxy --with-net-snmp --enable-ipv6 \
--with-libcurl --with-libxml2 --with-mysql=/usr/local/mysql/bin/mysql_config
make && make install

5.配置数据库

5.1 创建Zabbix数据库

MariaDB [(none)]> create database zabbix charset utf8 collate utf8_bin;"
MariaDB [(none)]> GRANT ALL PRIVILEGES ON zabbix.* TO 'zabbix'@'localhost' IDENTIFIED BY 'zabbix';
MariaDB [(none)]> flush privileges;"

5.2 导入zabbix表结构

MariaDB [(none)]> source database/mysql/schema.sql;
MariaDB [(none)]> source database/mysql/images.sql;
MariaDB [(none)]> source database/mysql/data.sql;

6.配置Zabbix Server

6.1 创建配置文件

vi /etc/zabbix/zabbix_server.conf


# 设置数据库IP
DBHost=127.0.0.1
# 设置数据库名称
DBName=zabbix
# 设置数据库账户
DBUser=zabbix
# 设置数据库账户密码
DBPassword=zabbix
# 设置日志存储路径
LogFile=/var/log/zabbix/zabbix_server.log

6.2 创建启动脚本

cp misc/init.d/fedora/core/* /etc/init.d/
chmod +x /etc/init.d/zabbix_server

vi /etc/init.d/zabbix_server


# 设置Zabbix工作目录
BASEDIR=/usr/local/zabbix

7.启动Zabbix Server

systemctl daemon-reload 
systemctl status zabbix_server.service
systemctl enable zabbix_server.service

8.配置UI

8.1 创建Nginx配置文件

vi /etc/nginx/conf.d/zabbix.conf


server {

    listen       80;
    server_name  localhost;    
    location /zabbix {

        root   /usr/share/nginx/html;
        index  index.html index.htm index.php;
        charset utf-8;

        access_log  /var/log/nginx/zabbix_access.log main;
        error_log  /var/log/nginx/zabbix_error.log;

        location ~* \.php$ {

        root           /usr/share/nginx/html;
        fastcgi_pass   127.0.0.1:9000;
        fastcgi_index  index.php;
        fastcgi_param  SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include        /etc/nginx/fastcgi_params;
        }
    }
}

8.2 创建UI文件

cp -r ui /usr/share/nginx/html/zabbix
chown -R zabbix:zabbix /usr/share/nginx/html/zabbix

8.3 重载Nginx

nginx -t
nginx -s reload
